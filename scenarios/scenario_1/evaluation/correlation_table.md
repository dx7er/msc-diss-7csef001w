## Interpretive observations

Three findings emerge from Scenario 1 that generalise beyond this run and feed the cross-scenario evaluation matrix:

1. Pure browser download actions (A02, A03, A05, A06, A07) cannot be attributed by any of the three project artefacts. Prefetch requires the file to have executed, Security auditing does not log HTTP fetches, and ShellBags record namespace navigation not network activity. This is a scope limitation of the artefact selection, not a failure of the tools that parse them.

2. Certificate-validation events (CAPI2 EID 4097) provide weak, host-issuer-level attribution for TLS sessions to download hosts and are the only per-download signal available in EVTX. Naming the issuer (Starfield for Adobe, DigiCert for Zoom, GlobalSign for Notepad++) is enough to pull the attribution above zero but not to CONFIRMED.

3. Install actions produce the strongest cross-artefact convergence, particularly when the installer uses MSI (Adobe, Zoom, Chrome, VLC): Prefetch captures the setup binary and follow-on runtime, MsiInstaller Application-log events name the product and record success, and Service Control Manager EID 7045 records service installation. NSIS-based installers (Notepad++) leave a Prefetch trace but no MsiInstaller trace, dropping to PARTIAL.
